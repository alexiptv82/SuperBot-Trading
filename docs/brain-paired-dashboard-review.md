# Paired Brain dashboard — read-only app change

This app change is based on main `d4865ddc`, separately from runtime PR#14. It adds `GET /api/brain/profiles` under the same authenticated session and `Cache-Control: no-store`. The original `/api/brain/status` remains compatible. No bot/runtime imports, control endpoint, trading action or source write is added.

The reader uses fixed `brain-hawk/brain.sqlite3` and `brain-bull/brain.sqlite3` paths below `BRAIN_ADAPTIVE_DATA_DIR` (default `/opt/superbot-brain-adaptive`). It validates the new runtime version, profile/account identity, method hash and PAPER trade identity. SQLite connections use `mode=ro`, `query_only`, a consistent transaction and a two-second deadline shared by the two new profiles. The old Brain read has its own existing two-second deadline. Only allowlisted fields leave the reader: no raw model inputs, source path, credentials or complete internal state.

The new runtime PR#14 extension records actual quote receipt timestamps, monotonic completed-step counters, an indexed event stream and explicit AI advice distinct from execution. Prices without a receipt timestamp remain stale; the reader does not stamp them with the current time. Gross floating equity uses the native account definition. Optional estimated net close/ROI uses the native fees, slippage and funding model; entry costs are included in that estimate even though already paid. A missing price makes equity unavailable. Partial realizations aggregate by account/position for all-history statistics; the last 20 realizations come from authoritative SQLite, not a potentially lagging optional export.

The PWA provides observation-only navigation between Hawk + Brain, Bull + Brain and the previous Brain account. Accounts are never summed or relabeled as each other. Profiles without a database say **not started**, with no fictional $1,000 wallet or inferred leverage. Per-position margin, saved leverage, notional, age, stop/target, entry source and reason are visible. It distinguishes AI proposals from actual positions and labels classical fallback, model pending/budget limits, fast data gaps and shared reserved API spending. Daily-stop display uses the actual selected profile limit (currently classical10%, previous Brain20%). Docker health/SHA/uptime stay unknown without independent attestation.

Polling remains a single abortable GET every30seconds after the previous request completes. An old backend returning404 for the new route falls back to the legacy GET; network errors clear stale values. Model text remains React-escaped; no trade controls are introduced. Navigation does not send orders or additional profile-specific requests.

Validation:41 Python reader/API tests, including WAL visibility/read-only preservation, long/short/DCA-residual margin, partial aggregation, missing/stale data, foreign identities, symlinks, deadline, authentication and no-cache. Ten React tests cover existing rendering/poll lifecycle plus profile isolation, unstarted accounts, proposal/source labels and text escaping. Production React build passes. Generated build output is not committed.

Release preparation: mount `/opt/superbot-brain-adaptive` read-only into the app and set `BRAIN_ADAPTIVE_DATA_DIR`. Do not create or mount the classic Hawk/Bull writable volumes. The app may be released before the new runtime: it retains the previous Brain view and honestly shows unstarted paired profiles. Runtime activation, spend-baseline acquisition and preservation of the previous Brain account are separate operational steps with verified backups; this app PR alone does not activate them.
